- **맥락**: 소유자 지시 "경기·순위·결과는 한국풋살연맹 자료 기반, FK리그 형식에 맞춰". 연맹 구단 소개의 선수 명단은 지난 시즌 등록 기준이라 26-27 이적·영입(구단 인스타그램 공지)과 다름.
- **결정**: futsal.or.kr 공개 페이지(구단 소개, 2025-26 FK1 일정·결과·순위, 경기 기록지, 2026 FK CUP)에서 수집해 `supabase/data/2025-26_kfl.sql` 로 저장소에 남기고, 운영 DB 는 관리자 계정 로그인(RLS 통과)으로 같은 내용을 반영. 인스타그램 공지(GOOD LUCK=이적, WELCOME=영입, 감독 교체)를 소유자가 전달한 내용으로 명단을 덮어쓴다. 소식 글은 `supabase/data/2026-27_club_news.sql`.
- **이유**: 연맹이 리그 공식 기록 보유처. 데이터 파일이 저장소에 있어 새 환경 재현·검토 가능.
- **버린 대안**: 연맹 사이트 실시간 크롤링 — 약관상 사전 허락 필요(I-013), HTTP 전용·불안정 / service_role 키로 직접 쓰기 — 앱에 비밀키를 두지 않는 원칙(SECURITY_GUIDELINES).

## D-009 | 2026-10-15 | 공개 데이터 캐시: 'use cache' + 태그 + cacheLife('minutes')
- **상태**: 채택
- **맥락**: Cache Components 에서 DB 조회를 정적 셸에 넣으면서도 관리자 저장은 즉시 보여야 함.
- **결정**: repo 조회 함수마다 `'use cache'` + `cacheTag(TAGS.x)`, 서버 액션에서 `updateTag(TAGS.x)`. 수명은 `minutes`(1분 재검증).
- **이유**: updateTag 로 저장 직후 반영(read-your-own-writes). 기본 캐시가 인스턴스 메모리라 다른 서버 인스턴스에는 태그 갱신이 안 닿을 수 있어 1분 상한을 둔다.
- **버린 대안**: `max` 수명 — 인스턴스 간 불일치가 길어짐 / 매 요청 조회 — 정적 셸 이점 상실.
