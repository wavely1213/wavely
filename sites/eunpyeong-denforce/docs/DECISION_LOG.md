## D-017 | 2026-10-15 | 구단소식 글에 상세 사진 여러 장 (news_posts.images)
- **상태**: 채택 (소유자 선택 — 대표 사진 1장 안 대신 "사진 4장 모두")
- **맥락**: 구단 인스타그램 유니폼 공개 게시물(사진 4장)을 구단소식에 옮기는데, 글에는 썸네일 1장만 넣을 수 있었다.
- **결정**: `news_posts.images text[]`(기본 빈 배열, 최대 10장) 열을 추가. 상세 화면은 사진이 있으면 사진 전부(원본 비율, PC 2칸·모바일 1칸 `components/news/NewsGallery`), 없으면 썸네일 한 장. 목록 카드는 썸네일, 없으면 첫 사진(BR-015). 관리자 폼에 여러 장 올리기·사진별 삭제(`ImagesField` ↔ `lib/admin/storage resolveImages`).
- **이유**: 구단사진·경기 화보처럼 여러 장 글이 앞으로도 많다. 별도 사진 테이블보다 배열 한 칸이 저장·RLS·캐시가 단순(기존 news_posts 정책 그대로). 썸네일과 사진을 나눠 두면 목록용 대표 이미지를 따로 고를 수 있다.
- **버린 대안**: 사진 테이블(news_images) — 순서·삭제 정리가 늘고 지금 규모에 과함 / 본문에 이미지 문법 넣기 — 관리자가 URL 을 다뤄야 함.
- **영향/제약**: 한 번 저장에 올리는 파일은 썸네일 포함 합계 4MB(서버 액션·Vercel 요청 본문 한도) — 사진을 고를 때(ImagesField)와 저장할 때(AdminForm `maxUploadBytes`, 폼 전체) 막고 나눠 저장하라고 안내. 요청이 한도를 넘으면 서버 액션이 실행되지 못하고 오류 화면으로 바뀌어 입력이 사라지기 때문. 순서 바꾸기는 없음(지우고 다시 올리기, I-022). 삭제 요청은 DB 의 현재 목록에 있는 URL 만 인정해 다른 파일을 지울 수 없다. 마이그레이션 `20261015120000_news_images.sql` (운영 반영 완료).

- **상태**: 채택 (D-012 의 "결과 표에는 승/무/패 배지 없음"을 대체)

- **영향/제약**: 승 색이 브랜드 블루와 분리됨 (D-005 컬러 체계 예외: 경기 결과 표시 전용).
