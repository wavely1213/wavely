# DOMAIN_KNOWLEDGE.md — 도메인 지식

> **목적**: 이 서비스의 용어·비즈니스 규칙·불변식을 기록한다. 코드만 봐서는 알 수 없는
> "서비스가 왜 이렇게 동작해야 하는지"의 원천. AI는 도메인 개념이 등장하는 작업 전에
> 이 문서를 확인하고, 여기 정의된 용어·규칙과 다르게 구현하지 않는다.
>
> **갱신 시점**: 새 개념·규칙이 확정될 때마다 즉시. 규칙 변경은 `DECISION_LOG.md`에도 기록.

## 1. 용어집 (Glossary)

> 코드 네이밍은 반드시 이 표의 영문 표기를 따른다. 같은 개념 = 같은 이름.

| 용어 (한국어) | 코드 표기 | 정의 |
|---|---|---|
| 골레이로 | `GK` | 골키퍼 |
| 픽소 | `FIXO` | 최후방 수비수 |
| 알라 | `ALA` | 측면 공격·수비 |
| 피보 | `PIVO` | 최전방 공격수 (축구의 FW에 해당) |
| 필드 플레이어 | `FP` | 골레이로 외 선수 (국가대표 이력 표기에 사용) |
| FK리그 | — | 한국풋살연맹 주관 세미프로 리그. 1부 슈퍼리그 / 2부 드림리그 |
| 홈/원정 | `isHome` | 홈구장 은평다목적체육관 |
| 구단소식 분류 | `notice` `news` `photo` `video` | 공지사항 / 구단뉴스 / 구단사진 / 구단영상 |
| 스폰서 등급 | `naming` `official` `partner` | 네이밍 스폰서 / 공식 스폰서 / 파트너 |

## 3. 비즈니스 규칙 (Business Rules)

> 각 규칙은 번호를 부여하고, 구현·테스트에서 이 번호를 참조한다 (예: `BR-001`).

- **BR-001**: 리그 순위는 승점 → 득실차 → 다득점 순으로 정렬한다 (`lib/repo.ts getStandings`). FK리그 공식 규정 확인 필요.
- **BR-002**: 경기 표기는 홈팀을 왼쪽에 둔다. 스코어도 홈:원정 순.
- **BR-003**: 메인 "다음 홈경기"는 `status = scheduled` 이고 `isHome` 인 가장 이른 경기. 현재 날짜가 아니라 상태값으로 판단한다 (정적 빌드).
- **BR-004**: 확인되지 않은 사실(선수 이름, 일정, 스폰서)은 실제처럼 쓰지 않는다. 자리표시는 "선수 N", "상대팀 A"처럼 명백히 가짜로 쓴다.

## 4. 불변식 (Invariants) — 절대 깨지면 안 되는 조건

- `finished` 경기는 반드시 score 가 있고, `scheduled` 경기는 score 가 null 이다.
- 팀명 표기는 `SITE.name`("서울은평 덴포스") 한 곳에서만 가져온다.

## 5. 상태와 흐름

경기: scheduled → finished (score 입력)

구단 팀명 변천: 서울은평 FS(2012) → 서울은평 나인티플러스 FC(2020) → 서울은평 ZD스포츠 FC(2023) → 서울은평 덴포스(2025, 덴포스 네이밍 스폰서)
