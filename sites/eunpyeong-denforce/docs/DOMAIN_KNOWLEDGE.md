# DOMAIN_KNOWLEDGE.md — 도메인 지식

> **목적**: 이 서비스의 용어·비즈니스 규칙·불변식을 기록한다. 코드만 봐서는 알 수 없는
> "서비스가 왜 이렇게 동작해야 하는지"의 원천. AI는 도메인 개념이 등장하는 작업 전에
> 이 문서를 확인하고, 여기 정의된 용어·규칙과 다르게 구현하지 않는다.
>
> **갱신 시점**: 새 개념·규칙이 확정될 때마다 즉시. 규칙 변경은 `DECISION_LOG.md`에도 기록.

## 1. 용어집 (Glossary)

> 코드 네이밍은 반드시 이 표의 영문 표기를 따른다. 같은 개념 = 같은 이름.

| 용어 (한국어) | 코드 표기 | 정의 |
|---|---|---|
| 골레이로 | `GK` | 골키퍼 |
| 픽소 | `FIXO` | 최후방 수비수 |
| 아라 | `ALA` | 측면 공격·수비. 표기는 "아라" ("알라" 아님) |
| 피보 | `PIVO` | 최전방 공격수 (축구의 FW에 해당) |
| 필드 플레이어 | `FP` | 골레이로 외 선수 (국가대표 이력 표기에 사용) |
| FK리그 | — | 한국풋살연맹 주관 세미프로 리그. 2025-26 부터 1부 FK1리그 / 2부 FK2리그 (이전 명칭 슈퍼리그 / 드림리그). 컵대회는 FK CUP |
| 대회 | `competition` | 경기의 대회명. 표기 형식 "2025-26 FK1리그", "2026 FK CUP" (연맹 표기 기준) |
| 홈/원정 | `isHome` | 홈구장 은평다목적체육관 (서울 은평구 진관1로 52, 네이버 장소 35069965) |
| 구단소식 분류 | `notice` `news` `photo` `video` | 공지사항 / 구단뉴스 / 구단사진 / 구단영상 |
| 스폰서 등급 | `naming` `official` `sub` `partner` | 네이밍 스폰서 / 메인 스폰서 / 서브 스폰서 / 후원사 — 높은 등급부터. /sponsors 는 등급별 묶음, 메인 띠도 이 순서 (D-059) |
| 포스팅 | `posting` | 구단 이름으로 올라온 바깥 글(블로그·카페·기사·영상) 모음. 원문 링크 카드 |
| 포스팅 분류 | `club` `news` `fan` `league` | 구단 포스팅(구단·구단 측 계정) / 뉴스(언론 기사·중계 매체) / 팬 포스팅(그 밖의 개인·다른 팀) / FK리그(한국풋살연맹 공식 유튜브 '한국풋살연맹 - KFL', D-032) |

## 2. 회원 등급·권한 체계

방문자 회원 기능 없음 (모든 페이지 공개). 관리자 화면 등급 (D-057, 값은 `admins.role`):

| 등급 | 코드 | 할 수 있는 일 |
|---|---|---|
| 최고 관리자 | `owner` | 모든 메뉴 + 관리자 › 관리자 계정(추가/등급 변경/미디어 권한/삭제). 한 명 이상 있어야 한다(DB 트리거) |
| 관리자 | `admin` | 모든 메뉴 (관리자 계정 관리는 빼고) |
| 미디어 | `media` | 구단소식/포스팅 글과 사진만. 계정마다 권한 4개(직접 공개 `can_publish` / 메인 배너 고정 `can_feature` / 글 날짜 정하기 `can_set_date` / 공개된 글 고치기 `can_edit_published`) — 모두 끄면 '검토 대기'(비공개)로만 저장, 날짜는 저장한 날 |

- **BR-028**: 구단 소유 사업자 — 상호 **풋볼아카데미**(대표 최경진, 사업자등록번호 110-19-57248, 사업장 경기도 고양시 덕양구 고양대로 1840, 1층(동산동), 업태 교육서비스/종목 축구). 푸터 맨 아래 오른쪽에 '상호 / 대표 / 사업자등록번호'를 보인다(관리자 › 홈페이지 내용 › 공통 '맨 아래 오른쪽 정보', 2026-10-19 소유자 지시). 사업자등록증의 생년월일 등 개인정보는 홈페이지에 싣지 않는다.
- **BR-027**: 미디어 계정이 올린 비공개 글은 **'검토 대기'** — 관리자 목록에 노란 배지, 대시보드 할 일 '검토 대기 구단소식/포스팅 N개'. 최고 관리자/관리자가 열어 '홈페이지에 공개'를 켜고 저장하면 공개된다 (소유자 "검토는 wavely1213 계정으로 내가 해서 최종 올릴 예정", D-057).

## 3. 비즈니스 규칙 (Business Rules)

> 각 규칙은 번호를 부여하고, 구현·테스트에서 이 번호를 참조한다 (예: `BR-001`).

- **BR-001**: 리그 순위는 승점 → 득실차 → 다득점 순으로 정렬한다. 그래도 같으면 팀명 가나다순 (개막 전 0점 표의 순서 고정, `lib/standings byRank`). FK리그 공식 규정 확인 필요.
- **BR-002**: 경기 표기는 홈팀을 왼쪽에 둔다. 스코어도 홈:원정 순.
- **BR-003**: 메인 "다음 홈경기"는 `status = scheduled` 이고 `isHome` 인 가장 이른 경기. 현재 날짜가 아니라 상태값으로 판단한다 (정적 빌드).
- **BR-005**: 리그 순위의 경기 수 = 승+무+패, 승점 = 승×3 + 무×1 (DB 생성 컬럼, 관리자는 승·무·패·득실만 입력). FK리그 공식 규정 확인 필요.
- **BR-006**: 관리자 = 로그인 + 이메일 인증 + `admins` 목록. 그 외 로그인 사용자는 일반 방문자와 같다 (읽기만).
- **BR-007**: 비공개(`published = false`) 소식은 관리자만 본다. 공개 사이트·목록·상세 어디에도 노출하지 않는다.
- **BR-004**: 확인되지 않은 사실(선수 이름, 일정, 스폰서)은 실제처럼 쓰지 않는다. 자리표시는 "선수 N", "상대팀 A"처럼 명백히 가짜로 쓴다.
- **BR-008**: 연맹 자료로 만든 화면(경기결과, 리그순위, 선수 기록)에는 "자료: 한국풋살연맹" 출처를 표기한다.
- **BR-009**: 도움은 연맹이 공개하지 않으므로 선수 상세에서 기록이 있을 때(>0)만 보여준다.
- **BR-010**: 메인 "경기" 섹션은 예정 경기가 있으면 지난 1 + 예정 2, 예정 경기가 없으면(시즌 휴식기) 최근 결과 3경기를 보여주고 '전체보기'는 경기결과로 간다.
- **BR-011**: 경기 일정·결과는 연맹 경기일정 양식의 표(라운드·경기일정·경기 대진표·경기장소·결과)로, 대회별로 표를 나눈다(연속된 같은 대회끼리, `lib/match.ts groupByCompetition`). 라운드·장소가 비어 있으면 '-' 또는 구분점(·) 없이 표시 (D-012). 결과 칸은 승(초록)·무(옅은 회색)·패(옅은 빨강) 박스 (D-013).
- **BR-012**: 리그순위 열 순서는 연맹과 같다: 순위·팀명·경기수·승점·승·무·패·득점·실점·득실차.
- **BR-014**: 스태프 직책에 '감독' 또는 '코치'가 들어가면 코칭스태프(사진 카드), 그 밖은 프런트(목록)로 보여준다 (`lib/staff.ts`, D-016).
- **BR-016**: 리그순위는 시즌(`season` = 경기의 대회명)별로 둔다. 리그순위 페이지 = 지금 시즌(`LEAGUE.currentCompetition`) 표 + '지난 리그' 목록(최근 시즌 먼저, 우리 최종 순위·승무패). 지난 시즌 화면 = 최종 순위 + 같은 시즌 연도("2025-26 …") 대회의 우리 종료 경기(리그·플레이오프, 연도 하나짜리 컵대회 제외). 경기 0인 팀은 순위 '-' (D-020).
- **BR-017**: 구단소식 본문의 주소(https://, www., 도메인/경로)는 링크로 보인다 — 바깥 주소는 새 창, 우리 홈페이지 주소(eunpyeong-fs.com, www/https 상관없이)는 같은 창 + 짧은 이름(선수 상세 '선수 소개 보기', 구단소식 '소식 보기', 그 밖은 도메인 뺀 경로). 이메일·@핸들은 링크가 아니다 (D-021, D-053).
- **BR-019**: 구단 연혁(공개 화면)에는 강등·패배 같은 부정적 표현을 쓰지 않는다 — 성적은 순위·입상만, 리그 이동은 '소속'으로 적는다 (소유자 지시 2026-10-16). 경기 결과·지난 리그 기록 화면은 사실 그대로 둔다.
- **BR-026**: **입단/테스트 문의는 홈페이지에서 받지 않는다** — 선수 등록은 정해진 시기에만 하므로 (2026-10-17 소유자 지시 "입단/테스트는 빼자", "어차피 선수등록은 시기가 정해져있으니까"). 문의 페이지 문의 분야는 스폰서십/제휴·아카데미/유소년·언론/취재·기타, 메인 바로가기 '문의' 카드 설명은 '제휴/후원'. 선수 모집은 시기에 맞춰 공지사항(트라이아웃 등)으로 알린다.
- **BR-025**: **2026-27 등번호는 확정 전까지 선수단에 비워 둔다** (2026-10-17 소유자 지시: "아직 넘버 확정이 아니라 중복도 생기네" — 예: 송민혁·강민원 둘 다 5번). 활동 선수 전원 `number = null`, 지우기 전 번호는 `supabase/data/2026-10-17_player_numbers_backup.sql`. 등번호가 없으면 선수 카드·상세에 번호를 표시하지 않고 같은 포지션 안에서 이름순. 선수 주소(slug `no-N`)는 그대로 둔다. 인사 소식 글에는 구단 발표 번호를 그대로 적는다. **김대현(옛 8번·18번, 둘 다 픽소)은 동명이인 두 사람이다** — 중복 등록으로 보고 합치지 말 것. **김종호도 동명이인 두 사람이다** — 2025-26 피보 김종호(옛 22번, 주소 `no-22`)와 2026-10-19 영입 아라 김종호(발표 30번, 전 화성FS, 주소 `kim-jongho`) (2026-10-20 소유자 판단 + 연맹 명단).
- **BR-024**: 홈페이지 글에는 **중간점(·)을 쓰지 않는다** — 구분은 슬래시: 띄어 쓴 구분은 ' / ', 붙여 쓴 묶음은 '/'(예: '엠블럼/유니폼'). 줄 머리 글머리표는 '- '. 관리자에서 글을 쓸 때도 같은 규칙 (D-047, 2026-10-17 소유자 지시).
- **BR-023**: 홈페이지 내용(관리자 › 홈페이지 내용)의 칸은 **비우고 저장하면 처음 값(코드 기본값)으로 돌아간다** — 빈 칸으로 화면에서 지우는 기능이 아니다. 목록(바로가기 카드 등)은 항목을 모두 지우면 그 섹션이 사라진다 (D-046).
- **BR-022**: 대외 문의 연락처는 단장 연락처(jonghbae@naver.com / 010-5135-0309)로 통일한다 — 푸터·문의 페이지 모두 관리자 › 구단정보의 문의 메일·전화 한 곳에서 나온다. 푸터의 '단장' 이름은 관리자 › 스태프의 직책 '단장'(현재 배종현)을 따른다 (D-044, 2026-10-16 소유자 지시). 예전 문의처: futbol10@naver.com / 02-6368-2308 (연맹 구단 소개 기준).
- **BR-021**: 구단소식 분류 — 안내·공고 성격(구매 안내, 선수·유소년 모집, 트라이아웃, 일정 변경·휴장 등 팬에게 알리는 글)은 **공지사항(notice)**, 사건을 전하는 기사(입단·이적·선임, 유니폼 공개, 스폰서 계약, 경기 결과)는 **뉴스(news)**, 사진 모음은 사진(photo), 영상은 영상(video). 소유자 지시 "공고 내용은 구단소식이나 뉴스가 아니라 공지사항으로" (2026-10-16, '유니폼 구매 안내'를 공지사항으로 옮김).
- **BR-020**: 인사 소식(입단·이적·선임·작별)은 한 사람에 글 하나, 기사형(했다체)으로 쓴다. 여러 명을 한 글에 목록으로 묶지 않는다 (D-033). 사실은 구단 발표 문구·발표일·등번호·포지션 등 확인된 것만.
- **BR-018**: 포스팅은 우리 구단(시기별 이름·풋볼아카데미·유소년 포함)이 글의 주제이거나 주요하게 다뤄진 것만 싣는다 — 리그 전체 기사 속 한 줄 언급, 다른 학원 광고의 코치 경력 한 줄, 같은 이름의 의류 브랜드(나인티플러스·ZD스포츠) 상품 글, 다른 '은평FS'(테니스 등), 여자팀(ZD스포츠 위민 등)은 뺀다. 분류: 구단 포스팅 = 구단·구단 측 계정(인스타그램 @eunpyeong_denforce, 유튜브 "서울은평FS 풋볼아카데미"·"ZD Sports Studio"·"최경진 풋살사관학교", 블로그 "덴포스 테베즈"·"ZD 풋살파크", 구단이 직접 올린 모집·공지 글) / 뉴스 = 언론 기사, 연맹·방송 채널(한국풋살연맹 KFL, KFATV, iTOP21sports, PMGSPORTS, 풋살코리아, 우리동네캐스터), 연맹 블로그 / 팬 포스팅 = 그 밖. 원문은 옮기지 않고 제목·짧은 요약·대표 사진·날짜(원문 게시일, 생방송은 방송 시작일, 한국 시간)만 둔다 (D-022).
- **BR-015**: 구단소식 사진 — 상세 화면은 상세 사진(`images`)이 있으면 그 사진 전부를 올린 순서대로, 없으면 썸네일 한 장. 목록 카드(공개·관리자)는 썸네일, 썸네일이 없으면 첫 사진 (`rows.ts toNewsPost`, D-017).
- **BR-013**: 연맹 시즌 제목·"자료: 한국풋살연맹" 표기는 실데이터(DB)일 때만 붙인다 (`repo.isLiveData`). 정적 자리표시 데이터에는 붙이지 않는다 (BR-004).

## 4. 불변식 (Invariants) — 절대 깨지면 안 되는 조건

- `finished` 경기는 반드시 score 가 있고, `scheduled` 경기는 score 가 null 이다.
- 팀명 표기는 `SITE.name`("서울은평 덴포스") 한 곳에서만 가져온다.

## 5. 상태와 흐름
