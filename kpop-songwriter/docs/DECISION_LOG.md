> 결정을 기록한다. 과거 결정을 뒤집기 전에 반드시 여기서 당시 이유를 확인한다.
>
> **기록 대상**: 스택·라이브러리 선택, 구조 결정, 데이터 모델 설계, 버리기로 한 대안,
> 보안/성능 트레이드오프. (사소한 네이밍·스타일 결정은 기록하지 않는다)

> **작성 규칙**: 최신 항목을 맨 위에 추가(append-only). 과거 항목은 수정하지 않고,
> 뒤집을 때는 새 항목으로 기록하고 이전 항목에 `→ D-XXX로 대체됨`만 표시한다.

## D-012 | 2026-10-07 | 웹사이트(mulgyeol.kr/music)는 같은 코드의 두 번째 빌드
- **상태**: 채택
- **맥락**: 소유자 요구 — mulgyeol.kr/music 웹사이트. mulgyeol.kr은 별도 저장소(wavely-web, 이 세션에서 접근 불가)가 배포한다.
- **결정**: `node build.mjs web` → `dist-web/music/` (완성 HTML, `<base href="/music/">`, 샘플 동봉). 이 폴더를 단독 Vercel 프로젝트로 배포하고 wavely-web에서 `/music` 리라이트. 빌드 상수 `__WEB__`로 문구만 바꾼다.
- **이유**: 코드 하나로 아티팩트·웹 동시 유지, wavely 앱 빌드(Expo)와 분리.
- **버린 대안**: wavely-web에 직접 넣기 — 접근 불가, 스택(Vite/React) 다름 / wavely Expo 빌드에 합치기 — mulgyeol.kr이 그 빌드가 아님.
- **영향/제약**: 웹은 AI 꺼짐(서버 키 결정 전), 저장은 브라우저만. 한글 파일명 다운로드는 정상(테스트 컨테이너는 UTF-8 로캘 필요).

## D-011 | 2026-10-07 | 가사 최적화: 규칙 기반 채점 + "오른 것만 반영" 개선 루프
- **상태**: 채택
- **맥락**: ROADMAP C — 최적화. AI 결과 품질이 들쭉날쭉해 기준이 필요.
- **결정**: AI 없이 라임(줄 끝 모음 일치 비율)·줄 길이 범위와 균형·코러스 훅 반복·분량으로 섹션 0~100점. 한/영 비율·제목-코러스·파트 균형은 곡 단위 점검. 자동 개선은 고칠 점을 AI에 주고 다시 쓴 뒤 점수가 오른 섹션만 반영(최대 2회).
- **이유**: 결정적·무료·즉시. 점수가 떨어지는 AI 결과가 덮어쓰지 않게.
- **버린 대안**: AI가 채점 — 비용·일관성 문제.
- **영향/제약**: 점수는 참고값. 줄 길이 범위는 어림값이라 실제 가사로 보정 필요(BACKLOG).

## D-010 | 2026-10-07 | "AI 학습" = 취향 학습 (프롬프트 주입), 파인튜닝 데이터는 내보내기만
- **상태**: 채택
- **맥락**: 소유자 요구 — AI 학습. 이 환경(아티팩트 sample)에서는 모델 학습 불가.
- **결정**: 👍/👎·이유·AI 초안을 고친 전후를 기록(최근 150개) → 프로필(작사·사운드·피할 것, 직접 또는 AI 정리) + 좋아한 예시·고친 방향을 모든 AI 프롬프트에 넣는다. 기록은 JSONL로 내보낸다.
- **이유**: 즉시 효과, 비용 없음, 사용자가 프로필을 직접 보고 고칠 수 있음.
- **버린 대안**: 파인튜닝 — 이 환경에서 불가, 데이터도 아직 적음.
- **영향/제약**: 취향 문서는 `data/users/<id>/_taste/items/taste`. AI 모듈은 `learn/context.js`로만 취향을 읽는다.

## D-009 | 2026-10-07 | 앨범 발매 반자동화: 앨범은 곡과 따로 저장, 큰 파일은 화면 메모리에만
- **상태**: 채택
- **맥락**: ROADMAP D — 발매 과정 반자동화. 마스터 WAV(수십 MB)·커버(수 MB)는 db 문서 한도(256KB)를 넘는다.
- **결정**: 앨범 문서는 `data/users/<id>/_albums/items/<albumId>`(로컬은 별도 키)에 메타데이터만. 마스터·커버는 이번 방문 메모리(`album/session.js`)에 두고 제출 zip을 만들 때 묶는다.
- **이유**: 저장 한도 회피, 원본 오디오를 서버에 남기지 않음.
- **버린 대안**: 곡 문서 안에 앨범 정보 — 한 곡이 여러 앨범(싱글·정규)에 실릴 수 있음.
- **영향/제약**: 새로고침하면 마스터·커버를 다시 넣어야 함 (BACKLOG에 보관 방법 등록). → 2026-10-07 IndexedDB 보관 추가(같은 브라우저에서는 남음).

## D-008 | 2026-10-07 | 마스터링을 브라우저 안에서 (BS.1770 측정 + 트루 피크 리미터)
- **상태**: 채택
- **맥락**: 소유자 요구 — 음원 퀄리티를 발매 가능한 수준으로. 발매 품질 음원은 Suno 생성 + 마스터링에서 나온다.
- **결정**: Suno 결과물을 받아 EQ·글루 컴프 → 목표 LUFS(기본 -14) → 4배 오버샘플링 트루 피크 리미터(-1 dBTP) → 44.1kHz 24/16비트 WAV.
- **이유**: Spotify·YouTube -14 LUFS / -1 dBTP 권장. 파일을 서버에 올리지 않고 처리.
- **버린 대안**: 외부 마스터링 서비스 연동 — 비용·계정 필요 / 12탭 보간 — 밝은 믹스에서 피크 1dB 넘게 놓침(ffmpeg 대조), 32탭으로 교체.
- **영향/제약**: 리미터 감소가 12dB를 넘으면 목표 음량을 포기하고 경고. 긴 곡은 처리 수 초~십수 초.

- **버린 대안**: MusyngKite(CC BY-SA, 용량 큼) / 런타임 외부 fetch — CSP 차단.
- **영향/제약**: CC BY 출처 표기 필요 (사운드 탭·패키지 README·CREDITS.md).

## D-006 | 2026-10-07 | 음악 엔진: 샘플 없는 Web Audio 신스 + 2초 단위 오프라인 렌더
- **상태**: 채택
- **맥락**: 아티팩트는 외부 오디오 파일을 불러올 수 없고(CSP), 노트마다 필터를 만들면 WAV 렌더가 100초 곡에 56초 걸렸다.

- **이유**: 렌더 3.6초로 단축, 외부 파일 불필요.
- **버린 대안**: Tone.js — 의존성 추가 대비 이득 작음 / 샘플 사운드폰트 — CSP로 로드 불가(인라인 시 용량 큼).
- **영향/제약**: 앱 안의 소리는 데모 품질. 발매 품질은 Suno·DAW에서 (I-001).
