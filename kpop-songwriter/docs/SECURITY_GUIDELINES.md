# SECURITY_GUIDELINES.md — 보안 지침

> **목적**: 커뮤니티 서비스는 회원 정보와 사용자 생성 콘텐츠(UGC)를 다루므로
> 보안 사고 한 번이 서비스 신뢰를 무너뜨린다. 인증·입력·시크릿·개인정보를 다루는
> 모든 작업 전에 이 문서를 읽는다.

---

## 1. 시크릿 관리

- API 키·비밀번호·토큰·DB 접속 정보는 **코드·커밋·로그·문서·주석 어디에도 남기지 않는다.**
- 시크릿은 환경변수(또는 시크릿 매니저)로만 주입: 현재 시크릿 없음 (API 키를 쓰지 않는 구조 — D-002)
- `.env*`는 `.gitignore`에 포함되어 있는지 확인. 새 시크릿이 필요하면 변수명만 정하고 값 설정은 소유자에게 요청한다.
- **코드에서 하드코딩된 시크릿을 발견하면 즉시 보고한다** (이미 커밋됐다면 키 회전 필요 — 소유자 판단).

## 2. 입력 검증 — 모든 외부 입력은 불신한다

- 사용자 입력(폼, 쿼리 파라미터, 헤더, 업로드 파일)은 서버 측에서 반드시 검증한다. 클라이언트 검증은 UX용일 뿐이다.
- 검증 도구/패턴: AI 응답은 `ai.js`/`ai-music.js`에서 필드별 범위 검사 (BR-004)
- **SQL 인젝션**: 쿼리는 항상 파라미터 바인딩/ORM 사용. 문자열 조립 쿼리 금지.
- **XSS**: UGC(게시글·댓글·닉네임)는 출력 시 이스케이프. HTML 허용이 필요하면 화이트리스트 새니타이저 사용: HTML 허용 안 함 — 모든 텍스트는 `h()`가 텍스트 노드로 넣는다 (innerHTML 금지)
- **업로드 파일**: 확장자·MIME·크기 검증, 실행 가능 파일 거부, 저장 시 파일명 재생성.

## 3. 인증·인가

- 인증 방식: claude.ai 계정 (플랫폼 처리)
- 비밀번호를 직접 다룬다면 bcrypt/argon2 해싱 (직접 구현 금지, 검증된 라이브러리 사용).
- **인가는 모든 요청에서 서버 측 검증**: "내 글만 수정 가능" 같은 규칙은 UI 숨김이 아니라 서버에서 소유권을 확인한다 (IDOR 방지).
- 관리자 기능은 별도 권한 체크. 권한 등급 정의는 `DOMAIN_KNOWLEDGE.md` 참고.

## 4. 개인정보 (커뮤니티 서비스 핵심)

- 수집하는 개인정보 목록: 없음 — 불투명 사용자 id만 경로에 사용. 레퍼런스 오디오는 저장하지 않음 (BR-005)
- 개인정보는 **로그·에러 메시지·분석 이벤트에 남기지 않는다.**
- 회원 탈퇴 시 처리 방침: 해당 없음 (플랫폼 계정)
- 법적 요구사항(개인정보처리방침 등)의 판단·결정은 소유자 몫이다. AI는 관련 작업 시 사실 확인이 필요한 지점을 짚어주기만 한다.

## 5. 기타 규칙

- **Rate limiting**: 로그인·가입·글쓰기 등 남용 가능 엔드포인트에 적용: 플랫폼이 sample 호출 제한 (`rate_limited`). 앱은 사용자 클릭에만 호출, 루프 재시도 금지
- **CORS**: 허용 오리진 명시. `*` 금지.
- **에러 응답**: 내부 정보(스택 트레이스, 쿼리, 경로) 비노출.
- **의존성 취약점**: `DEPENDENCY_POLICY.md` 참고. audit 경고 발견 시 보고.
- HTTPS 전제. 쿠키는 secure 플래그.

## 6. AI 작업 시 보안 체크리스트

인증·입력·개인정보 관련 코드를 작성/수정했다면 완료 보고 전에 확인:

- [ ] 새 입력 경로에 서버 측 검증이 있는가
- [ ] 새 조회/수정 경로에 소유권·권한 확인이 있는가
- [ ] 시크릿·개인정보가 코드/로그에 남지 않는가
- [ ] 쿼리가 파라미터 바인딩을 사용하는가
- [ ] UGC 출력이 이스케이프되는가

보안상 애매한 트레이드오프(예: 편의 vs 보안)는 선택지를 제시하고 소유자가 결정한다.
