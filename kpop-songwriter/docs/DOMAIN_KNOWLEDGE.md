# DOMAIN_KNOWLEDGE.md — 도메인 지식

> **목적**: 이 서비스의 용어·비즈니스 규칙·불변식을 기록한다. 코드만 봐서는 알 수 없는
> "서비스가 왜 이렇게 동작해야 하는지"의 원천. AI는 도메인 개념이 등장하는 작업 전에
> 이 문서를 확인하고, 여기 정의된 용어·규칙과 다르게 구현하지 않는다.
>
> **갱신 시점**: 새 개념·규칙이 확정될 때마다 즉시. 규칙 변경은 `DECISION_LOG.md`에도 기록.

---

## 1. 용어집 (Glossary)

> 코드 네이밍은 반드시 이 표의 영문 표기를 따른다. 같은 개념 = 같은 이름.

| 용어 (한국어) | 코드 표기 | 정의 |
|---|---|---|
| 곡 | `song` | 프로젝트 단위. 컨셉·가사·편곡·멜로디·음색·레퍼런스·버전을 가진다 |
| 섹션 | `section` | 곡 구조의 한 부분 (Intro, Verse, Pre-Chorus, Chorus, Post-Chorus, Rap, Bridge, Dance Break, Hook, Outro) |
| 멤버 | `member` | 파트를 부르는 가상의 가수. 이름·포지션·음역(`voice`)·보컬 톤(영어) |
| 파트 분배 | `members` (섹션 필드) | 섹션을 맡은 멤버 id 목록 |
| 편곡 | `music` | 곡 전체 BPM·키 + 섹션별 편곡(`music.sections[id]`) + 음색(`sounds`) |
| 마디 | `bars` | 4/4 한 마디 = 16칸(16분음표, `step`) |
| 코드 도수 | `chords` | 스케일 도수 1~7. 마디마다 하나, 마디 수보다 짧으면 반복 |
| 에너지 | `energy` | 1(조용)~5(폭발). 드럼 밀도·벨로시티·필인에 영향 |
| 멜로디 음표 | `melody[]` `{s,l,d,syl}` | 섹션 안 시작 칸, 길이 칸, 스케일 인덱스(0=으뜸음 4옥타브), 가사 음절 |
| 음색 | `sounds[inst]` | `variant`(음색 종류), `tone`(밝기 0~1), `vol`, `mute` |
| 레퍼런스 | `reference` | 참고 곡. 분석값(`analysis`)·좋은 점(`likes`)·메모·반영 여부(`use`) |
| 버전 | `version` | 곡 스냅샷. 메타는 곡에, 본문은 별도 저장 |
| 마스터 설정 | `master` | `{preset, target}` — 음색 프리셋과 목표 LUFS. 오디오는 저장하지 않음 |
| 앨범 | `album` | 발매 단위. 트랙(`tracks[{songId, isTitle, 크레딧, isrc}]`)·메타데이터·커버 설정·일정 체크·홍보 문구 |
| 마스터 파일 | `masters[songId]` | 트랙에 넣은 발매용 WAV와 점검값 (방문 중 메모리만) |
| 취향 | `taste` | `{enabled, profile{lyrics, sound, avoid}, log[]}` — 사용자 단위 |
| 반응 기록 | `taste.log[]` | `{kind, rating(1/-1/0=고침), text, before, after, reasons, context{ref}}` |
| 진행 플래그 | `song.progress` | `{arranged, suno, mastered}` — 저절로 판단할 수 없는 단계의 완료 표시 |
| 샘플 묶음 | `pack` | 악기·음색별 샘플 모음 (`samples/<key>.json`) |

## 2. 사용자 권한 체계

| 등급 | 할 수 있는 것 |
|---|---|
| 소유자(아티팩트 주인) | 자기 곡 읽기·쓰기 (`data/users/{self}`) |
| 공유받은 사람 (Contributor 이상) | 자기 곡을 따로 만들고 저장. 다른 사람 곡은 볼 수 없음 |
| Viewer/Commenter | 저장 불가 (화면만) |

## 3. 비즈니스 규칙 (Business Rules)

- **BR-001**: 자동 분배 — Intro·Dance Break·Outro는 멤버 없음, Chorus·Post-Chorus·Hook은 전원, Rap은 래퍼 포지션 우선, 나머지는 보컬을 돌아가며 (3명 이상이면 2명씩).
- **BR-002**: Suno 내보내기에서 비워 둔 반복 섹션(예: Chorus 2)은 앞의 같은 타입 섹션 가사를 그대로 쓴다.
- **BR-003**: 같은 타입이 3번 이상이면 마지막 Chorus는 "Final Chorus"로 표시한다.
- **BR-004**: AI 응답은 선택지(악기 id, 드럼·베이스 id, 도수 1~7, 에너지 1~5, 마디 1~16, 멜로디 범위)로 검사·보정 후에만 반영한다.
- **BR-005**: 레퍼런스 오디오 파일은 저장·업로드하지 않는다. 분석 숫자와 메모만 저장한다. 레퍼런스의 멜로디·가사는 복제하지 않는다.
- **BR-006**: 곡별 버전은 최근 30개까지 (`MAX_VERSIONS`). 복원 시 복원 직전 상태를 자동으로 버전에 남긴다.
- **BR-007**: 예시 곡은 수정하기 전까지 저장하지 않는다.
- **BR-008**: 마스터링 기본값 -14 LUFS / -1 dBTP / 44.1kHz. 리미터 감소 12dB 초과가 필요하면 목표를 포기하고 알린다. 앞뒤 무음 정리 기본 켬(-60dBFS 기준, 앞 50ms·뒤 0.5초 남김), 끝 페이드 아웃은 선택.
- **BR-010**: 발매 일정은 발매일 기준 D-42(마스터 확정)·D-35(커버·메타)·D-28(유통 제출)·D-21(저작권)·D-14(피칭·티저 계획)·D-7(티저)·D-3(등록 확인)·D(발매)·D+1·D+7·D+14.
- **BR-011**: 제출 점검 — 오류: 제목·아티스트·수록곡·작사/작곡 크레딧·마스터(WAV, 44.1kHz↑, 16bit↑)·커버(정사각형) 누락. 경고: 곡 수가 종류 범위 밖, 타이틀곡 없음, 발매 4주 이내, ©/℗ 미기재, 트루 피크 > -0.5 dBTP, 음량 -18~-6 LUFS 밖, 커버 3000 미만.
- **BR-012**: 같은 대상(context.ref)에 대한 평가는 마지막 것만 남는다. 고친 기록은 평가와 따로 남는다. 고친 기록은 입력이 4초 멈춘 뒤 남긴다.
- **BR-013**: 취향 블록은 해당 종류(kind)의 좋아한 예시 최대 4개, 고친 예 최대 3개, 싫다는 이유 상위 4개만 넣는다. "AI 요청에 반영"을 끄면 넣지 않는다.
- **BR-014**: 가사 점수 — 코러스류(Chorus·Hook·Post-Chorus): 라임 30·음절 30·훅 반복 30·분량 10, 그 외: 라임 45·음절 40·분량 15. Intro·Outro·Dance Break와 비워 둔 반복 섹션은 채점하지 않는다. 자동 개선 기준 70점.
- **BR-015**: 발매 진행 7단계 완료 기준 — 컨셉(주제·스토리·키워드 중 하나), 가사(빈 섹션 없음 + 점수 70↑), 편곡(편곡 탭에서 무엇이든 바꿈, `progress.arranged`), 멜로디(음표 1개↑), Suno 생성(가사·스타일 복사 또는 패키지 받기, `progress.suno`), 마스터링(마스터 결과·앨범 마스터·`progress.mastered`), 발매 준비(앨범의 꼭 고칠 것 0개).
- **BR-016**: 보컬 음역(MIDI) — 여성 고음 60~81, 여성 중음 57~77, 여성 저음 53~72, 남성 고음 50~71, 남성 중음 45~67, 남성 저음 40~62, 랩은 제한 없음. 섹션 음역은 부르는 멤버 음역의 겹치는 부분. 기본값은 그룹 형태(보이그룹·남성 솔로=남성 중음, 그 외 여성 중음), 래퍼 포지션=랩. AI 멜로디는 음역을 넘으면 옥타브를 옮겨 넣는다.
- **BR-017**: 되돌리기는 곡·앨범 단위, 최근 40단계. 버튼·선택 같은 동작은 한 단계씩, 타이핑은 2초 안 연속 입력을 한 단계로 묶는다. 버전 목록·id는 되돌리지 않는다.
- **BR-018**: 앨범 트랙 간 음량(통합 LUFS) 차이가 3 LU를 넘으면 경고한다 (`ALBUM_LOUDNESS_GAP`). 스트리밍 앨범 재생은 곡 사이 상대 음량을 그대로 두므로 의도하지 않은 차이는 그대로 들린다. 발라드 등 의도한 차이는 무시 가능.
- **BR-019**: 싱크 가사(LRC)는 태그 없는 가사지의 빈 줄을 뺀 줄마다 시작 시각 `[mm:ss.xx]`(100분의 1초)을 붙인다. 머리에 `[ti:]`·`[ar:]`·`[al:]`·`[length:mm:ss]`. 맞춘 뒤 가사가 바뀌거나 덜 맞췄거나 순서가 꼬이면 제출 패키지에서 빼고 점검표에서 경고한다. 맞춘 마스터와 지금 마스터 길이가 1초 넘게 다르면 경고.
- **BR-020**: 유사 표현 점검 결과는 가사 내용 열쇠(lyricsKey)와 함께 저장한다. 가사가 바뀌면 '다시 점검'. 확인할 줄이 남으면 점검표 경고, 점검을 안 했거나 낡았으면 참고 항목. 걸린 줄을 제안으로 바꾸면 그 줄만 바뀌므로 열쇠를 지금 가사로 갱신한다. AI가 가사에 없는 줄을 짚으면 버린다.
- **BR-021**: 번안 가사의 부를 단위 — 한국어·영어는 음절, 일본어는 모라(가나 한 글자=1, 작은 ゃゅょぁぃぅぇぉゎ는 앞 글자에 붙음, っ·ん·ー=1, 괄호 애드립 제외, 남은 영어는 음절). 원문 음절 수와 2 넘게 차이 나면 '멜로디에 안 맞을 수 있음'. 원문 가사가 바뀌면 '다시 번안'. 비운 반복 섹션은 앞 섹션 번안을 쓴다.
- **BR-009**: CC BY 샘플을 쓴 데모를 공개할 때는 출처를 표기한다 (사운드 탭·패키지 README).

## 4. 불변식 (Invariants) — 절대 깨지면 안 되는 조건

- 모든 섹션은 `music.sections`에 정확히 하나의 편곡 항목을 가진다 (`normalizeMusic`이 보장).
- 멜로디 음표는 겹치지 않고 `s + l <= bars * 16`.
- 곡 문서에는 버전 본문(`data`)을 넣지 않는다 (256KB 한도).
- 사용자 데이터는 `data/users/<본인 id>/` 아래에만 쓴다.

## 5. 상태와 흐름

곡: 예시(`example: true`, 미저장) → 수정 시 내 곡(자동 저장) → 삭제
작업 흐름: 컨셉·멤버 → 구조·가사 → 편곡 → 멜로디 → 사운드 → (레퍼런스) → Suno 스타일 → 내보내기 → 버전

## 6. 정책 메모

- Suno 입력 한도 (V4.5·V5·V5.5 Custom 기준, 2026-10 웹 확인): 가사 5000자(V4 이하 3000자), 스타일 1000자, 제목 80자(가정) (`constants.js` SUNO_LIMITS). 넘친 글자는 경고 없이 잘림 — Suno 변경 시 갱신
- 레퍼런스 분석은 앞 240초, 11025Hz로 다운샘플
- WAV 데모: 44.1kHz 16bit 스테레오, 피크 0.98로 정규화
