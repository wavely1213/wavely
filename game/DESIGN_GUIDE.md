# 파장 WAVELENGTH — 디자인 가이드 · 남은 작업

이 문서는 두 부분이다.

- **1장 확정 규칙** — 이미 정해졌고, 앞으로 어떤 작업을 하든 지켜야 하는 것. 바꾸려면 근거를 남기고 바꾼다.
- **2장 남은 작업** — 지금 해야 하는 디자인 작업 전부. 우선순위 · 손댈 곳 · 완료 기준까지.

기준선 측정치는 5장에 있다. 작업 후 그 수치를 다시 재서 비교한다.

**이 게임은 이제 두 화면(웹·앱)으로 나간다.** 규칙을 지키는 방식이 달라졌으니
1.7을 먼저 읽는다 — 어디를 고치면 양쪽에 반영되고, 어디를 고치면 한쪽만 바뀌는가.

관련 문서: 시스템·데이터 구조는 [`README.md`](./README.md).

## 1. 확정 규칙

### 1.1 색은 의미에 1:1로 고정

화면에 탄이 40발 깔려도 읽혀야 한다. 색을 장식으로 쓰지 않는다.

| 토큰 | 라이트 / 다크 | 무엇에만 쓰는가 |
|---|---|---|
| `--c-signal` | `#d97757` | 플레이어 기체 · 아군 탄 · 추진기 발광 |
| `--c-drift` | `#5d8fc2` / `#6a9bcc` | 군체 · 적 탄 · 보스 · 육각 차폐 |
| `--c-moss` | `#788c5d` / `#94ab72` | 코어 · 보급품 등 **회수 가능한 것** |
| `--c-dust` | `#b0aea5` | 계기 · 배경 파형 · 중립 표식 |
| `--c-fg` / `--c-field` | 잉크 / 지면 | 글자 · 외곽선 / 플레이필드 바닥 |

- 새 색을 만들지 않는다. 필요하면 `shade(base, amt)`로 기존 토큰에서 파생한다.
- 텍스트에는 `-t` 접미 토큰(`--c-signal-t`, `--c-drift-t`)을 쓴다. 면 색을 그대로 글자에 쓰면 라이트에서 대비가 깨진다.
- 오렌지↔블루 조합은 적록색약에서도 안전한 축이다. 이 축을 유지하는 한 색맹 대응은 따로 필요 없다.
  다만 **색만으로 구분하지 않는다** — 아군 탄은 세로 막대, 적 탄은 원처럼 형태도 같이 다르게 한다.

### 1.2 두 테마를 같은 밀도로 설계

다크는 잉크 필드, **라이트는 종이 필드**로 군체가 뒤집힌다. 라이트는 다크의 반전이 아니라 별도 디자인이다.

- `prefers-color-scheme`(OS)과 `:root[data-theme]`(뷰어 토글)을 **양방향 모두** 대응한다. 컴포넌트는 항상 토큰을 거쳐 스타일링하고, 미디어쿼리 안에서 직접 색을 쓰지 않는다.
- 새 화면을 만들면 두 테마 스크린샷을 모두 확인한다. 하나만 보고 넘어가지 않는다.

### 1.3 캔버스 렌더 3원칙

작업하며 실제로 밟은 함정에서 나온 규칙이다. 새 아트를 붙일 때 반복해서 걸린다.

**① 구조선은 화면 좌표, 면은 모델 좌표**

외곽선·이음새 굵기를 모델 좌표(`lineWidth = 1.1`)로 두면 5배 확대에서 테두리도 5배가 되어 스티커처럼 보인다.

```js
const lw = 1.3 / sc;          // 구조선: 배율과 무관하게 화면상 굵기 고정
g.lineWidth = lw;             // 외곽선
g.lineWidth = lw * .85;       // 패널 이음새
// 그라디언트 · 베벨 같은 '면' 효과만 모델 좌표를 따른다
```

**② 하드웨어 색에 `C.fg`를 쓰지 않는다**

`C.fg`는 테마에 따라 뒤집힌다. 노즐·포드 같은 금속 부품에 쓰면 다크에서 새하얘진다.

```js
g.fillStyle = shade(base, -.66);   // O — 도장색 파생
g.fillStyle = shade(C.fg, -.05);   // X — 다크에서 흰색
```

**③ 배율별 LOD를 반드시 둔다**

같은 함수가 게임 중(1배)과 프리뷰(2.9~5배)에 모두 쓰인다. 큰 쪽 기준으로 그리면 작을 때 뭉개지고, 작은 쪽 기준으로 그리면 클 때 빈약하다.

```js
const hi = sc >= 1;
if (!hi) { /* 단색 + 외곽선으로 끝 */ return; }
/* 이하 풀디테일 */
```

**보조 규칙**

- 타원을 얼굴 위치에 두지 않는다. 조종석을 타원으로 두었더니 확대 시 얼굴처럼 읽혀 각진 캐노피로 바꿨다.
- 세부 좌표는 그리기 코드가 아니라 데이터에 둔다(`HULL`, `DETAIL`). 새 기체는 두 줄 추가로 같은 마감을 받는다.
- 파티클·흔들림은 `REDUCED`(`prefers-reduced-motion`)를 반드시 확인한다.

### 1.4 타이포는 역할로 나눈다

| 역할 | 토큰 | 쓰는 곳 |
|---|---|---|
| 계기 · UI | `--font-ui` | HUD, 메뉴, 버튼, 라벨 |
| 내러티브 | `--font-story` | 스토리 대사, 기체·탑승자 소개문 |
| 수치 | `--font-num` | 점수, 코어, 스탯, 형식번호 (`tabular-nums` 필수) |

계기와 내러티브를 서로 침범시키지 않는다. 대사에 산세리프를 쓰면 관제 로그처럼 읽히고, HUD에 세리프를 쓰면 계기판이 무너진다.

> ⚠️ 현재 `Poppins`/`Lora`는 **로드되지 않는다.** 웹폰트를 링크하지 않았고 둘 다 시스템 폰트가 아니다.
> 실제로는 폴백(Century Gothic / Trebuchet / Georgia)이 뜬다. 2장 P2-10 참조.

### 1.5 레이아웃

- 세로 2:3 스코프 하나. 모든 메뉴는 그 **안에서** 열린다. 웹페이지에 게임을 끼워넣은 형태로 만들지 않는다.
- 가로 스크롤 금지. 넓은 내용은 자기 컨테이너에서 `overflow-x: auto`.
- 필드 논리 해상도는 480×720 고정. 좌표를 하드코딩할 때 이 기준을 쓴다.

### 1.6 성능 예산

- **시간에 관한 것은 전부 `dt` 로.** 프레임 수로 세면 120Hz 기기에서 다른 게임이 된다.
  - 주기적으로 일어나는 일(연사·적 사격)은 남은 시간을 **이월**한다 —
    `cd = 주기` 로 덮으면 프레임 경계에서 초과분이 사라져 실제 주기가 늘어난다.
  - 연출을 뿌릴 때 `Math.random() < 0.8` 같은 **프레임당 확률을 쓰지 않는다.**
    초당 개수로 잡고 `개수 × dt` 로 환산한다(저프레임에서는 정수부만큼 한꺼번에).
  - 프레임마다 한 점씩 남기는 궤적도 같은 문제다. 시간 간격으로 찍고,
    프레임이 그보다 길면 그 사이 위치를 **보간해서** 나눠 찍는다.
- 외부 요청 **0**을 유지한다. CDN·폰트·이미지 링크 금지, 전부 인라인 또는 코드 생성.
- 풀디테일 패스는 화면당 소수 오브젝트에만(플레이어 1 + 보스 1 + 카드 4). 군체는 수가 많으므로 경량 패스를 별도로 유지한다.
- 파일 크기 기준선 **150KB**(UTF-8 바이트). 폰트를 인라인하면 이 숫자가 크게 뛴다 — 결정 전에 P2-10을 읽는다.
- `draw()` 실비용은 최대 부하에서 0.5ms(중앙값). 프레임 시간 16.7ms는 vsync 상한이라 예산을 못 보여 준다.

### 1.7 코어와 타깃 — 어디를 고쳐야 양쪽에 반영되는가

게임 로직과 **그리기**는 `src/core/`에 있고 웹·앱이 함께 쓴다.
바깥 세계에 닿는 곳은 `core/host.js`의 지점들뿐이고, 타깃이 그걸 자기 구현으로 채운다.

| 고치는 것 | 어디 | 양쪽에 반영되나 |
|---|---|---|
| 기체·군체·보스·이펙트·배경 | `core/draw.js` | **된다** |
| 격납고 카드 아트 · 치장 스와치 · 타이틀 프리뷰 | `core/draw.js` | **된다** |
| 색 토큰의 의미 | `core/color.js` | 된다 (값은 타깃이 넣는다) |
| 데이터·밸런스·해금·가격 | `core/data.js` `run.js` `shop.js` | **된다** |
| 색 값 | 웹 `index.template.html` CSS 변수 / 앱 `app/src/theme.js` | 아니다 — **둘 다 고친다** |
| 화면 배치·버튼·내비게이션 | 웹 `src/web/` / 앱 `app/` | 아니다 |
| 안내 문구 | 타깃별 (「Space」 같은 말은 그 조작이 있는 쪽에서만 맞다) | 아니다 |

두 규칙:

- **그림은 코어에서 그린다.** 앱은 `src/native/skia2d.js`로 같은 Canvas2D 인터페이스를 Skia 위에 만든다.
  새 아트를 앱 쪽에 따로 그리기 시작하면 두 화면이 갈라진다.
- **색 값을 한쪽만 고치지 않는다.** `node game/test/app.mjs`가 13개 토큰을 대조해 막아 준다.

>

각 항목은 **현재 → 목표 → 손댈 곳 → 완료 기준** 순이다.

### P0 — 품질 격차가 눈에 보이는 것

#### P0-1. 군체 마감이 기체에 뒤처진다 ★ 가장 먼저

- **현재** — 기체는 금속 그라디언트·베벨·이음새·노즐 발광까지 갔는데, 군체 4종은 단색 폴리곤 + 표식 몇 개다. 한 화면에 같이 있으면 격차가 바로 보인다.
- **목표** — 군체도 조립품으로 읽히게. 다만 **수가 많으므로 기체와 같은 비용을 쓸 수 없다.** 저비용 버전을 따로 설계한다.
  - 세로 2단 그라디언트(위 밝게/아래 어둡게) — 그라디언트 객체는 종류별 1회 생성 후 재사용
  - 상단 하이라이트 1줄 + 하단 그늘 1줄 (베벨 전체 대신 선 2개)
  - 피격 시 흰 플래시 2프레임 (지금은 파티클만이라 맞았는지 불확실)
  - 파괴 직전 상태에 노출 배선/불꽃 1점
- **손댈 곳** — `drawEnemy()`. 그라디언트는 모듈 스코프에 캐시하고 테마 변경 시 무효화(`readColors` 훅).
- **완료 기준** — 최대 부하(군체 17 + 보스 + 탄 25)에서 프레임 시간 중앙값이 기준선(16.7ms) 대비 +2ms 이내. 기체와 나란히 놓은 스크린샷에서 마감 급이 같아 보일 것.

#### P0-2. 5개 구역의 배경이 전부 똑같다

- **현재** — `drawBackdrop()`이 `G.stage`를 참조하지 않는다(확인함). 정적 지대와 근원이 시각적으로 구분되지 않아, 진행감이 숫자로만 존재한다.
- **목표** — 구역마다 배경이 확실히 다르되, **탄 가독성을 해치지 않는 선**에서. 각 구역의 이름이 이미 방향을 정해준다.

  | 구역 | 배경 방향 |
  |---|---|
  | 1 정적 지대 | 지금 그대로 — 기준값. 파형 진폭 최소 |
  | 2 간섭 구역 | 파형 2겹이 서로 어긋나며 간섭 무늬. 리벳 열 밀도 ↑ |
  | 3 반향의 벽 | 지나간 파형이 지연되어 한 번 더 흐름(잔상 레이어) |
  | 4 백색 소음 | 파형이 무너져 미세 노이즈 필드로. 격벽 이음새 사라짐 |
  | 5 근원 | 아래에서 위로 역류. 화면 상단에 광원 하나 |
  | 6+ 잔향 | 4·5를 섞고 색상만 서서히 탈색 |

- **손댈 곳** — `drawBackdrop()`에 `G.stage` 분기. 구역별 파라미터(진폭·겹수·유속·노이즈량·이음새 유무)를 `BACKDROP[stage]` 데이터로 빼고 그리기 코드는 하나로.
- **완료 기준** — 5구역 스크린샷을 나란히 놨을 때 이름만 보고 매칭 가능. 각 구역에서 적 탄이 배경에 묻히지 않을 것(다크·라이트 모두).

#### P0-3. 라이트 테마에서 `moss` 소형 텍스트 대비 미달

- **현재** — 측정치 **3.49**. 큰 글씨(19px 코어 잔액)는 3.0 기준을 넘어 통과하지만, 10~11px로 쓰이는 곳(`.stat.up b`, `.row .st b`)은 본문 기준 4.5에 미달한다.
- **목표** — 라이트 전용 텍스트 토큰 `--c-moss-t`를 추가해 소형 텍스트에만 적용. 면(코어 표식·보급품)은 지금 색 유지 — 그건 대비 기준 대상이 아니다.
- **손댈 곳** — `:root` / `:root[data-theme="light"]`에 `--c-moss-t: #5a6b45` 정도 추가 후, `.stat.up b`·`.row .st b`·`.log` 계열이 그 토큰을 쓰게.
- **완료 기준** — 라이트에서 4.5 이상. 다크 값(7.31)은 유지.

#### P0-4. 모바일 터치 타겟이 작다

- **현재** — 390px 폭 실측: `.tab` 66×**34**, `.buy` 55×**33**, `.iconbtn` 69×**25**. 권장 44×44 미달.
- **목표** — 시각적 크기는 그대로 두고 **히트 영역만** 44px로 넓힌다. 촘촘한 계기판 느낌을 잃지 않기 위해서다.
- **손댈 곳** — 해당 클래스에 `min-height: 44px`(탭·버튼) 또는 `::after`로 투명 확장 영역. 인접 타겟 간 최소 8px 간격 확보.
- **완료 기준** — 390px에서 모든 상호작용 요소가 44×44 이상, 겹침 없음. 데스크톱 레이아웃 변화 없을 것.

## 3. 내가 정할 수 없는 것

작업 전에 답이 필요하다.

1. **폰트 인라인 여부** (P2-10) — `Poppins`/`Lora`가 실제로 로드되지 않아 폴백으로 뜨고 있다.
   라틴 서브셋을 인라인하면 +40~80KB. 지금 파일이 150KB라 체감이 크다.
   앱도 같은 문제를 반대 방향으로 갖는다(기기 시스템 폰트를 쓴다) —
   인라인하면 양쪽이 같은 서체가 되므로 결정 하나로 둘이 정리된다. 라이선스 확인 주체도 정해야 한다.
2. **우선순위 확인** — 이 문서는 "보이는 격차 → 감각 → 완성도" 순으로 정렬했다.
   다른 기준(예: 플레이 타임 늘리기, 앱 스토어 출시)이 우선이면 순서가 바뀐다.

> P3-16 탑승자 시각화는 ⓒ(벡터 실루엣) 방향으로 정리됐다 —
> 얼굴 대신 **계기판식 식별 표식**(회피율만큼 열린 링 + 육각 + 형식번호)으로 구분한다.
> 일러스트 조달이 필요 없어졌다.

## 4. 작업 루프

이 저장소에서 디자인 작업은 **눈으로 확인하면서** 한다. 추측으로 넘어가지 않는다.
다만 눈으로 못 보는 것들은 검사가 대신 본다 — 아래 넷은 손대기 전후로 돌린다.

```
node game/build.mjs            # src/ → index.html
node game/test/core.mjs        # 규칙 (브라우저 없이 · 몇 초)
node game/test/regress.mjs     # 웹 회귀 · 반응형 · 대비 · CSS 유실
node game/test/skia2d.mjs      # 앱이 웹과 같은 그림을 그리는지 (픽셀 대조)
node game/test/app.mjs         # 앱 컴파일 · 코어 이름 · 패키지 API · 색표 일치
node game/test/app-render.mjs  # 앱 화면을 실제로 그려 전 흐름을 눌러 본다

node game/test/balance.mjs --progress   # 검사가 아니라 측정 — 밸런스가 흔들렸는지
```

이 검사들은 **눈으로 안 잡히던 결함을 실제로 잡아서 생겼다.** 무엇을 막고 있는지 알아두면
새 검사를 어디에 둘지도 보인다.

| 검사 | 실제로 잡은 것 |
|---|---|
| CSS 규칙 유실 | 떠 있는 중괄호 하나가 `.wallet { display:flex }`를 통째로 삼켰다 |
| host 배선 | `fontFamily`를 안 꽂아 캔버스 글자가 조용히 다른 서체로 나왔다 |
| 글자 대비 | 출격 버튼 3.12, 잠긴 기록 1.39 |
| 반응형 | 프리뷰 `min-height` 바닥값이 큰 폰에서 48px를 화면 밖으로 밀었다 |
| 패키지 API | 존재하지 않는 `useKeepAwake` 옵션 |
| 색표 일치 | 앱과 웹의 토큰이 갈라지는 것 |
| 앱 렌더 | 훅 순서·없는 프로퍼티·잘못된 상태 전이 — 바벨은 통과해도 여기서 걸린다 |

손으로 보는 것:

1. 헤드리스 Chromium으로 실제 렌더 → PNG
2. **다크/라이트 × 데스크톱(760px)/모바일(390px)** 네 조합 확인
3. 확대 렌더(3~5배)로 디테일 검증 — 1배에서 안 보이던 문제가 여기서 나온다
4. 성능에 영향 있는 변경이면 5장 기준선과 비교

기체·군체를 손댈 때는 **1배·2.9배·5배를 한 캔버스에 나란히** 그려 LOD가 모든 크기에서 성립하는지 본다.

리팩터링처럼 "보이는 게 안 바뀌어야 하는" 작업은 **바꾸기 전 파일을 남겨 두고 픽셀 해시로 대조**한다.
배경이 움직여서 전체 스크린샷은 매번 다르므로, 정지된 요소(카드·스와치·실루엣)만 골라 비교한다.

## 5. 기준선 (2026-07-30)

새 작업 후 이 수치를 다시 재서 비교한다.

**성능** — 최대 부하(5구역 보스 + 군체 13 + 적 탄 28 + 파티클 23), 760×1000 다크

| | 값 |
|---|---|
| `draw()` 중앙값 | **0.5 ms** |
| `draw()` p95 | 1.5 ms |
| 프레임 중앙값 | 16.7 ms (vsync 상한) |

**지금까지 고친 정합성 결함**

| 결함 | 어떻게 드러났나 |
|---|---|
| 런 종료 중복 실행 → 코어 중복 적립 | 「출격 중단」 연타 (결과 화면 전 700ms) |
| 사망 후 700ms 동안 HUD 조작 가능 | 그 사이 정지 → 중단으로 코어 2배 |
| 일시정지 중 HUD가 키보드 포커스로 도달 | 오버레이는 마우스만 가린다. Tab → Enter로 폭탄 소모 |
| 손상된 저장으로 게임이 죽고 복구 불가 | `eq.weapon: 99` → `WEAPON[99].shots` 예외 |
| 사망 후 무적이 풀리면 런 종료가 반복 호출 | 코어를 브라우저 없이 돌리자 드러났다 (웹은 결과 화면이 루프를 멈춰 가려져 있었다) |
| 떠 있는 중괄호가 CSS 규칙을 삼킴 | `.wallet`이 죽어 지갑이 납작하게 나왔다 |
| `host.fontFamily` 미배선 | 캔버스 글자가 폴백 서체로 나왔다 |
| 프리뷰 `min-height` 바닥값 | 큰 폰·노트북에서 타이틀이 화면 밖으로 밀렸다 |
| 연사 쿨다운이 초과분을 버림 | 표시보다 느리게 쏘고, 그 손실이 기기 주사율에 따라 달랐다(60Hz −10.2% / 120Hz −4.4%) |
| 연출을 프레임당 확률로 뿌림 | 배기 파티클이 120Hz 에서 두 배, 잔상 길이가 30Hz 에서 두 배 |

`inert`는 입력 경로만 막는다. **불변식은 함수 안에서 다시 확인해야 한다** — 세 번째 항목의 교훈이고,
다섯 번째 항목은 그 교훈을 코어 쪽에서 다시 배운 것이다.

**미변경 확인**

- `host.reduced` 적용 지점 3곳 — 파티클 수, 배기 파티클, 화면 흔들림.
  히트스톱·연출류를 추가하면 함께 늘려야 한다.
- 잔향(무한 모드)의 대사는 6구역까지만 있다. 7구역 이후는 대사 없이 흘러간다.
